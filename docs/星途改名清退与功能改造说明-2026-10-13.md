# 星途 StarPath：改名、清退与功能改造说明

更新日期：2026 年 10 月 13 日
用途：管理层阶段汇报、产品范围确认及后续开发交接
范围：`shilijia-agent` 已提交改造及当前工作区的后续实现

## 1. 阶段结论

相对于最初的 LobsterAI 桌面项目，当前已完成星途品牌替换、项目与对话工作空间改造、旧界面和废弃代码清退，并新增公司平台登录、固定模型网关、余额同步、套餐查询、本地语音和办公文档配套能力。

macOS 已有真实模型对话和文档成果验证。公司登录、余额及套餐已有客户端实现与本地契约验证；真实账号、真实邮箱、Windows/Linux 和正式发行仍有待办。

**当前适合按“核心客户端已形成，正在完成商业服务和发行验收”汇报，不能按“全平台正式商业发布完成”汇报。**

### 1.1 最新决定

| 项目 | 当前最终口径 |
| --- | --- |
| 邮箱 | 已恢复“设置 → 邮箱”，支持多账号配置、默认账号、启停、删除与连接测试；不再归类为已清退功能 |
| 套餐 | 已接公司套餐与订阅查询接口，展示套餐、额度、有效期和历史；购买、订单与支付后续补充 |
| 回答区域 | 沿用官方 2026.9.23 回答链路，不继续叠加星途正文、思考和流式收尾定制 |
| 文件打开 | 正文 Markdown 文件链接由系统打开；文件卡片、产物标签继续使用右侧预览 |
| 梦境 | 保持退役，旧后台自动整理任务明确关闭；普通记忆保留 |
| 外观与渠道 | 外观仅浅色、深色、跟随系统；远程连接仅展示微信、钉钉、飞书、企业微信 |
| 公司平台 | 仅使用现有接口；另一套 new-api/gateway 的代码、配置、部署和数据库没有在本轮修改 |

### 1.2 状态说明

- **已实现**：代码存在，不代表已用真实账号或目标系统验收。
- **已本地验证**：自动测试、构建或模拟接口验证通过。
- **已实际客户端验证**：在对应系统的 Electron 窗口操作过，验证范围按记录限定。
- **待真实服务/跨系统验收**：仍需真实账户、邮件服务或对应操作系统。
- **后续开发**：尚未实现，不作为当前交付能力。

本文以当前实现为准。历史方案中“邮箱已清退”“套餐待接入”“正文链接全部右侧打开”等描述，已被后续决定替代。

### 2.1 有意保留的旧标识

改名没有采用全仓字符串替换。历史数据库字段、部分 IPC、运行时工具 ID、备份格式及兼容标识继续保留；项目、对话、记忆、用户文件和旧凭据不随品牌替换删除。

原项目及第三方依赖的许可证、版权和来源声明继续保留。产品改名、独立编写部分技能，不等于整个项目或第三方依赖均为星途原创。

### 4.7 本地语音

- 普通麦克风入口使用本机识别，避免依赖平台尚未开放的转写模型。
- 安装包带引擎和许可证，首次由用户主动下载约 190 MB 模型，支持真实进度、取消、重试和完整性校验。
- 有模型时点击开始说话，再次点击结束并转文字；结果追加草稿，不自动发送。
- Escape、取消、切换对话及迟到响应相互隔离；本地识别音频不上传、不落盘。

已验证下载、取消清理、实际引擎对中英文合成短句的识别，以及原生客户端聆听/取消。真实人声、噪声、方言、长句和 Windows/Linux 准确率待验收。

### 4.8 启动与稳定性

- 统一开发/生产窗口恢复，限制自动重试，持续失败进入手动恢复页。
- 增加静态启动保护和错误出口，不以估算百分比冒充启动进度。
- 本地生产窗口使用固定资源快照，减少新构建清空旧窗口延迟资源导致的白屏。
- 预览增加局部错误边界，单个文件失败不卸载整个会话。
- 修复生产 PDF 中文字体/CMap 加载，损坏文件后可恢复打开正常文件。
- 定位活动客户端混用重建前后运行时造成的工具执行失败；恢复后已有真实 Word 生成和预览证据，并明确禁止覆盖活动运行时目录。

## 5. 对普通对话与周边能力的影响

| 场景 | 当前判断 |
| --- | --- |
| 普通文字对话、思考、历史和工具执行 | 核心链路保留，有回归及限定模型的实际验证；不代表所有模型均已验收 |
| 公司平台未登录 | 启动门禁阻止进入工作空间，是明确的产品变化 |
| 没有有效模型密钥/模型权限 | 需要先配置和验证平台密钥；客户端不虚构可用模型或备用厂商 |
| 文档/本地文件操作 | 能力保留；历史目录和文件已删除时仍会失败 |
| 正文链接和文件卡片 | 打开方式不同：正文系统打开，卡片/标签右侧预览 |
| 普通记忆与梦境 | 普通记忆保留，梦境自动整理停用 |
| 邮件办公 | 配置流程已恢复；实际邮件服务仍需联调 |
| 图片/视频生成 | 原生媒体链路仍依赖旧账户和媒体服务，不能算已由当前公司登录替换完成；其他技能/MCP 能力按各自配置核实 |
| 云分享与站点发布 | 仍依赖旧业务接口，当前不能列为公司平台已完成接入的服务 |
| 在线市场与自动更新 | 自有服务地址/策略未全部确定，默认关闭或使用离线内容 |
| 远程渠道与第三方扩展 | 当前入口与执行结构保留，实际收发/安装/升级按专项验收 |

结论是“尚未发现清退导致普通对话核心链路断裂的证据”，而非“所有周边功能完全不受影响”。
