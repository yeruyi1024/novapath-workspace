# 技能、插件与 MCP 的维护

这三者是不同的扩展方式，并不需要每项功能都同时具备三者。

| 类型 | 在项目中的作用 | 自有开发 | 外部来源与更新 |
| --- | --- | --- | --- |
| 技能 | `SKILL.md` 说明工作步骤，可附 Python/JS 脚本及资源 | 在 `SKILLs/` 添加目录、声明版本并维护默认配置和显示名称 | 支持本地目录、SKILL.md、ZIP、远程 ZIP、GitHub、npm、ClawHub；用户技能通过安装/升级流程更新 |
| 插件 | 扩展运行时能力、消息渠道等可执行功能 | 按固定运行时的插件接口开发、测试和打包 | 支持 npm、ClawHub、Git、本地；当前更新检查覆盖 npm 和 ClawHub，Git/本地需明确更新来源 |
| MCP | 把本地进程或远程服务中的工具提供给模型调用 | 可编写自己的 MCP 服务，配置启动或远程连接 | 工具能力由对应服务维护；客户端负责连接、配置、凭据、故障提示及兼容验证 |

技能可以指导使用 MCP 工具或插件提供的能力；插件也可以附带技能。MCP 工具不必须配备技能。技能是工作说明，不等于每次对话都重新下载软件。

## 现有文档能力

`SKILLs/skills.config.json` 中 DOCX、XLSX、PPTX、PDF 默认启用；已存在的用户启用/关闭状态优先，不能为了恢复默认覆盖用户选择。随包 Python 文档运行时提供 python-docx、openpyxl、python-pptx、pypdf、reportlab 等库，供文件生成、读取和修改。入口为 `src/main/libs/documentRuntime.ts`，使用 `STARPATH_PYTHON`，不能依赖开发机 Python 路径。

这些能力处理文档文件，不代表直接操控已经打开的 WPS 窗口。标准文档操作无需安装 WPS；旧格式转换、OCR、复杂排版渲染及部分公式计算可能需要额外组件，不能声称所有高级功能已经随包提供。右侧支持 DOCX、XLSX/XLS、CSV/TSV、PPTX、PDF 等已有渲染器；不支持的格式提供系统应用打开入口。

2026-10-15 按用户要求恢复四项原官方工具至正常技能目录，当前本地同步版本为 2.1.1；完整 OOXML 校验、Word 原编辑器、HTML 转 PPT 和 PDF 标注入口重新可执行。用户最新决定为先用原官方技能，自编助手暂停，不作为默认或缺依赖时的兜底；源码暂留待老板决定。功能变化须老板评审，发行许可检查保持阻止状态，当前不得直接打包发布。详见[恢复及验收记录](../../specs/bugfixes/2026-10-15-document-capability-restore.md)。

本地重新准备时，先按各自锁文件执行 `npm ci --prefix SKILLs/docx`、`npm ci --prefix SKILLs/pptx`，再执行 `npm run setup:document-runtime`；不要在活动客户端使用的目录里重建。HTML 转 PPT 需要可用的 Chrome/Chromium，PDF 栅格化需要 Poppler，公式重算需要 LibreOffice；这些外部工具未自动纳入本次安装包。原工作流需要 pandoc/markitdown 等依赖而环境未配置时，应明确说明依赖缺口，不自动改用自编助手或宣称原流程已完整执行。

## 发布与升级责任

- 随包技能由我们维护版本、测试并随客户端发布；`src/main/skills/skillManager.ts` 负责同步和升级备份恢复。
- 随包插件在 `package.json` 的 `openclaw.plugins` 中固定版本。上游作者维护其代码，我们负责选择版本、兼容测试、配置入口与发行。
- 用户安装的扩展与随包版本分别管理。当前没有公司自建插件仓库，也没有自动升级所有扩展的策略。不能把网络来源可更新描述成无需维护。
- 自有平台专属能力由我们开发；上游故障先定位版本与接口，确需修改时留下固定版本补丁及回退说明。
- 升级验证包括来源及许可证、运行时/SDK 兼容、启停、升级失败、旧配置恢复及目标系统运行；不得在用户对话中静默升级可执行插件。

## 本次替换与来源规则

DOCX、XLSX、PPTX、PDF 的 2.0.0 版工作说明和辅助脚本由星途独立编写，采用 MIT。Word 批注和文本修订、PPT 文本替换与排序、XLSX 检查和可选重算、PDF 合并/拆页/表单填写均有实际入口。原受限材料完整移至仓库外的本地审计目录，不进入新的安装包，也不作为新实现的代码来源。该备份是本地记录，不在 Git 中传播。

升级新版本时先准备完整新目录，再将旧目录保存在用户数据的 `skill-backups/` 中，位于技能发现目录之外。保留凭据；失败或中断时恢复旧目录。用户文件不销毁，历史对话和技能启用状态不重置。

其他开源技能、运行时、字体仍是第三方材料。保留原始 MIT、Apache、OFL 等许可声明，不能改署名为星途。各独立许可证只覆盖其对应材料，仓库整体 MIT 不覆盖带其他条款的资源。未知来源须记录待核对，不能当作原创。

外部笔记兼容入口保留；新安装默认关闭，仅在用户明确请求时连接。已有启用状态不被强制改写。不得自动安装外部服务的 CLI、索取其他平台的密钥或冒充星途存储服务。内置技能创建说明已适配星途工具环境，不默认依赖某品牌模型 CLI。

`resources/THIRD_PARTY_NOTICES.md` 是发行声明索引，实际许可证随资源保留。`scripts/verify-bundled-skill-licenses.cjs` 在 `beforePack` 阻止已知受限材料和缺少匹配声明的字体进入包；打包和运行时裁剪保留许可证，不再默认过滤 LICENSE、AUTHORS 或 CONTRIBUTORS。这个检查是已知问题防回归，不是法律授权证明。

详细变更和验收见 `specs/refactors/2026-10-11-owned-document-skills.md`。Windows/Linux 原生执行与全量历史依赖、旧模板和资产的来源复核仍需单独完成；不能仅靠改名承诺全库不存在侵权。
