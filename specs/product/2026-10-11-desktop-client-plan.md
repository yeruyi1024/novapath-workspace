# 聚合平台桌面客户端开发与验收计划

更新日期：2026年10月13日。

公司 PR #1 要求英文品牌调整为 NovaPath，本地展示已按此更新。原应用身份、数据目录及协议继续保持兼容；历史截图中的 StarPath 是调整前名称。

产品目标是把现有桌面项目包装为公司聚合平台的客户端，并完成可演示、可内测、可发行的分阶段交付。当前处于第一阶段，界面已有可保留的版本，下一步优先核对现有改动并跑通真实模型对话和文件成果预览。

## 产品定位与已确定的交互

公司现有 New API 聚合平台承担模型网关职责。桌面客户端承担项目、对话、本地文件和成果展示；当前代码使用 OpenClaw 运行任务。账户、计费和模型权限需要按公司后台协议接入。

用户已确定以下要求：

- 改造当前桌面客户端，产品面向多个操作系统；兼容目标包含 macOS、Windows 和 Linux。
- 主界面围绕项目与对话组织，支持新建项目、项目内新对话、无项目新对话以及对话分组。
- 项目可以关联本地目录，文件路径按当前对话的工作目录解析。
- 点击 AI 回复中的文件引用或成果卡片，在当前对话右侧预览；独立的本地文件预览导航已移除。
- 第一版外观已获用户认可，后续优先完善使用流程和兼容性。
- 品牌确定为“星途 NovaPath”，定位为 AI 工作空间，品牌语为“智能规划，持续执行”。
- 外观仅保留浅色、深色、跟随系统三个主题选项；这里的“三个”不是设置导航数量。
- 模型接入收敛到公司平台。当前提供网址与 API Key，后续按公司后台协议接入平台登录与固定服务地址；移除其他服务商和高级模型编辑入口。

## 本轮设置模块范围

主界面保留已认可的第一版。设置采用左侧功能导航和右侧编辑区域，常用设置优先展示，低频功能按需展开。

| 层级 | 首版功能 | 处理方式 |
| --- | --- | --- |
| 必须 | 星途网关地址、API Key、模型同步、连接测试、默认模型 | 模型与平台页优先展示；复用现有自定义服务商与运行配置 |
| 必须 | 语言、通知、文件成果自动展示、系统代理、数据备份 | 通用设置保留真实可用的控制项；必要维护入口可访问 |
| 必须 | 浅色、深色、跟随系统，界面与代码字号 | 外观页只显示三个主题，移除配色图库和 AI 皮肤入口 |
| 可选，保留 | 记忆、快捷键 | 快捷键在常用设置中；记忆在高级设置中，沿用现有文件与检索能力 |
| 已清退 | 其他模型服务商与高级模型配置 | 删除服务商编辑、第三方登录、Coding Plan、模型参数与导入导出界面；平台连接保存后停用其他旧服务商，保留旧记录用于迁移 |
| 必须保留 | 插件、技能与 MCP 连接器 | 插件在“平台与工具”中直接可达；技能默认展示常用项，MCP 默认展示已安装项 |
| 可选，折叠 | 消息渠道、邮箱、浏览器、自动记忆整理、运行维护、实验功能 | 放入高级设置；不作为首次使用的必填步骤 |
| 待后台协议 | 账户、余额、套餐、消费与充值 | 后续阶段接入，当前不展示模拟数字或无效操作 |

品牌变化与本地存储身份分开：应用继续使用既有数据目录和数据库，确保已有项目、对话与设置不因改名消失。平台连接使用独立的运行时服务商标识，不覆盖已有连接记录；网关模型 ID 不受内置服务商的模型退役列表影响。平台连接保存后，仅该连接可启用；停用平台不会回退到其他旧服务商。未配置平台前保存通用设置不迁移已有模型连接。

网关同步请求真实的 OpenAI 兼容模型列表；空列表、无效响应、网络或权限错误时保留原有配置。同步结果用于模型选择，连接测试另行发起一次简短对话请求。实际平台域名与账户协议仍待配置。

本轮设置与品牌改动的 185 项相关测试、修改文件 ESLint、Electron 主进程类型检查和完整生产构建已通过。macOS 桌面检查覆盖三个主题切换、模型同步与去重、默认模型选择、连接测试、401 提示、取消后不保留测试连接，以及设置保存；品牌改名后已有项目仍可见。Windows 安装契约测试已通过，Windows 与 Linux 实际运行仍待验收。

## 第一阶段执行顺序

### 一 核对现有改动

整理当前已修改的模块、保留的功能入口与缺陷清单。每项归入品牌包装、项目对话、文件成果、模型运行或平台兼容，标注代码实现和实际验证状态。

品牌与敏感信息检查覆盖界面、图标、导出内容、默认服务地址、日志、配置及打包资源。凭据检查记录文件位置和脱敏结果。保留上游许可证、第三方声明及维持数据和运行时兼容所需的内部标识。

输出：现有改动清单、待修缺陷、待配置的公司信息。第一版外观作为后续验收基线。

### 二 跑通真实网关对话

准备当前系统的 OpenClaw 运行时，使用公司提供的测试网关地址、测试账户或密钥及可用模型。验证配置保存、模型选择、流式回复、停止、继续、连接失败和鉴权失败。

New API 推理地址通过模型配置接入。客户端原有账户服务地址对应另一组后台接口，账户接入在第二阶段适配。

输出：可重复的真实对话演示步骤、问题记录和修复结果。

### 三 验收项目与文件成果

围绕一段真实对话检查完整流程：创建项目并选目录、开始对话、AI 读取或生成文件、点击回复引用在右侧预览、继续对话、重启后恢复历史。

同时检查无项目对话和对话归组。归组保持已有对话的工作目录；移除项目保留对话与本地文件。验证中文、空格、百分号、井号、相对路径和 Windows 盘符及网络共享路径。

输出：通过或失败的核心用例记录。缺陷修复后复测对应流程。

### 四 完成基础跨系统验收

在 macOS、Windows 和 Linux 检查启动、窗口控制、侧栏、输入、文件选择、目录读取与预览。记录系统版本、运行时、应用版本及结果。路径单元测试与实际系统测试分别记录。

输出：平台验证表、仍存在的限制和第一阶段验收结论。根据实际结果确定第三阶段支持的最低系统版本与发行架构。
