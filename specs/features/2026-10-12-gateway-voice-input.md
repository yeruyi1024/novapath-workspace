# 星途输入框语音输入

## 问题与范围

旧版录音入口依赖原厂商账户和实时转写后端，当前平台连接无法使用。用户要用说话代替打字，不是录音文件管理。复用麦克风采集和 WAV 编码，在输入框增加“语音输入”，说完后点“完成”，只填入当前输入框，由用户决定发送。接到已配置星途网关的 `/audio/transcriptions`，不保存录音，不恢复旧账户入口，不把密钥放到渲染进程。

## 行为与验收

- 用户点击麦克风后先检查平台是否提供兼容转写模型；缓存目录没有时刷新网关 `/models`，不改变对话模型。
- 用户点击开始才请求麦克风；最长 60 秒，结束后上传 WAV 并把文字追加到当前草稿，不自动发送。
- 模型未开放、权限拒绝、空音频、无识别结果、网络/认证/额度错误明确提示。
- 取消、关闭、切换对话或页面时停止采集、取消请求，迟到的结果不污染其他草稿。
- 主进程限制受信窗口、音频格式/大小、单窗口并发、超时与重定向；不保存录音，不打印凭据或转写内容。
- 相关回归测试、改动文件 lint、构建及主进程编译；浅深色/窄窗口/键盘 UI 验证。麦克风真机与实际平台音频转写单独记录。

## 状态

客户端代码与异常路径验证完成，真实语音识别待平台开放。

- 修复 Electron 编译错误，以及旧录音停止后清空新录音对象的竞态；启动和连接失败会释放麦克风与 AudioContext。
- 28 项相关测试通过，覆盖取消启动/请求、旧 flush、新采集、权限拒绝、最大时长、平台超时、凭据读取失败和音频边界。
- 隔离页面使用模拟音频验证“说话 → 完成 → 文字追加到已有草稿”，不自动发送；另验证权限拒绝、能力未开放和英语深色窄窗口。
- 真实 macOS 客户端查询平台能力，网关没有返回兼容转写模型。仅开放了对话模型，因此不会请求麦克风或伪装识别成功。
- 统一服务器语音服务是建议的后续接入方式；当前仓库没有部署服务或更改网关管理配置。用户不需要填写单独的语音模型设置。

真实麦克风采集、识别准确率、转写服务与 Windows/Linux 原生运行仍待验收。详细集成结果见 [内测验收记录](../../docs/development/acceptance-2026-10-12.md)。
