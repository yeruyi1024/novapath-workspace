## 已确认的需求

- 能力范围是语音输入转文字（ASR），不是大语言模型部署，也不包含文字转语音播报（TTS）。
- 计划由公司自己的云服务器承载识别服务。
- 当前可用服务器只有 CPU，没有 GPU；后续方案必须以 CPU 环境为前提评估。
- 改造方向是替换或扩展现有本地识别，具体采用哪种方式尚未确定。
- 最初按用户要求只保存项目记录，供其他人整合 PR；用户后续明确要求起草 PR，现已将本需求与许可审查一并写入既有 PR 正文。

## 当前实现与本次边界

当前普通麦克风入口使用本地识别：录音结束后转换为文字，回填当前草稿，由用户决定发送。现有客户端也保留了远程转写适配代码，但这不代表公司自建服务已经部署或接通。

另一个 new-api / gateway 平台继续只读。这项需求不授权修改其代码、接口、部署、配置或数据库。若后续自建 ASR 需要独立服务，须在审查后的范围内另行准备，不能借此补改该平台。

## 请老板审查的事项

| 事项 | 待确认内容 |
| --- | --- |
| 是否开展 | 是否同意推进公司 CPU 服务器自建 ASR |
| 使用方式 | 云端作为默认、本地继续保留，还是提供可选方式 |

| 试点范围 | 内部测试对象、服务器负责人、验收人与正式启用条件 |

## 审查通过后的工作顺序

1. 根据老板结论明确范围，补齐服务器规格、鉴权和音频处理要求。
2. 在 CPU 测试环境验证候选识别方案，使用受控样本测量识别质量、耗时、内存和并发。
3. 形成正式改造设计，明确客户端接入、服务端接口、超时取消、错误提示、数据处理和回退方式。
4. 在独立环境实现与联调，保留现有草稿回填、停止、取消和迟到结果隔离行为。
5. 按平台完成客户端及服务器验收，再按批准范围试点启用。

以上为后续顺序，不是本次已执行事项。老板未给出结论前维持现状。
