# 账户与订阅稳定性加固

状态：客户端修复完成，本地自动化与隔离组件预览通过；原生客户端和真实平台联调待验收。

## 问题与范围

用户要求优化本轮功能并避免影响正常使用。聚焦登录、账户状态刷新、个人资料和独立订阅的异步状态及弹窗交互；现有模型接入继续保留，gateway 只读，不修改主进程凭据、回答/流式处理、插件/技能/MCP、数据库或活动运行时。

初步发现：账户/余额 IPC 同步抛错时 pending 清理早于赋值，可能一直复用已完成请求；余额成功更新会使并发的账户检查失效；已登录状态处理失败响应时可能被不完整/不匹配快照替换。新弹窗未阻止主窗口快捷键，可能在查看套餐时切换对话或焦点。将先补充可失败的回归用例，再按实际结果修复，保留未相关的工作区改动。

## 验收与方法

- 同步异常、网络失败和超时后可以重试；保留已验证账户及上次数据，明确确认失效/退出时仍正常关闭工作空间。
- 并发余额/账户检查与退出、换账户相互隔离；拒绝跨账户/来源的数据。
- 账户/登录/订阅弹窗开启时，背景快捷键不能切换对话或将焦点移到输入区；关闭后快捷键恢复，Escape 和系统复制粘贴可用。
- 保持独立订阅布局、隐藏 quota、真实平台数据、只读购买状态；有效/历史订阅、加载、失败、空态仍可用。
- 有针对性的失败复现及回归测试、改动文件 lint、类型检查、隔离生产构建；本轮对近期功能进行完整 Vitest 回归，记录首次失败及复跑范围。通过 computer 隔离预览验证界面与快捷键，不重启用户客户端。原生/真实平台/跨系统与 GitHub CI 分别记录，不混称通过。

## 实现与结果

### 修复

- `maasSession.ts` 将 pending 清理移至 Promise finally，保证同步 IPC 异常后仍可重试；超时后迟到响应不能覆盖新结果。
- 失败响应保留同账户已验证数据，拒绝其他账户/来源的失败快照；主进程已清空账户但清理失败时仍关闭工作空间，不放宽启动验证。
- 同账户余额成功只发布数据，不递增登录版本，避免取消并发的会话失效检查。已退出/切换账户后的迟到余额仍受版本保护。
- 余额和订阅响应先校验来源，跨来源的空账户响应不能退出当前工作空间。
- 三个账户相关弹窗增加标记，App 全局快捷键入口检测弹窗并返回；保留原 Modal 的 Escape 和组件焦点管理，不改变其他弹窗及对话操作实现。
