# 启动主题闪烁与短信验证码反馈

状态：实现完成，本地测试与隔离 macOS 打包验证通过。

## 问题与行为

用户观察到启动 UI 白色后又变黑，且验证码缺少发送提示与重发倒计时。启动脚本仅添加 light/dark class，没有设置主题变量依赖的 data-theme；React 样式中的默认浅色变量因此可能覆盖深色启动页。PlatformSessionGate 严格模式取消的配置请求也可能提前初始化默认主题；账户检查阶段先渲染欢迎页加载状态，导致多个不同加载布局切换。

主窗口将安全、只读的初始浅深色快照通过现有 preload appInfo 暴露，首屏脚本以该快照为准设置 class/data-theme/background，普通浏览器仍用本地缓存/系统偏好。窗口背景与经典浅深色一致。复用纯展示加载组件，配置/账户检查结束前保持相同启动布局，不提前展示登录表单或开始账户请求之外的引擎行为。

验证码在真实 sendSMS 成功后显示脱敏号码与已发送提示，按钮明确显示发送中/几秒后重发/重新获取；计时以绝对期限计算，切回窗口即时刷新，过期提示明确。challenge 必须仍绑定当前手机号/平台，迟到响应不能恢复已失效的验证码。不虚构发送成功、不固定伪造 60 秒、不发送真实短信做自动测试。

## 边界与验证

只改客户端 startup/renderer 展示与 challenge 状态，不修改 gateway、认证协议、安全存储策略、cookie/令牌持久化、模型、对话、插件运行或当前用户偏好。保留现有 API 提供的 retryAfter/expiresIn 和登录处理器。

验证初始浅/深色及系统/缓存冲突、严格模式异步取消、发送成功/失败/过期/换号/迟到响应、后台恢复计时、中英文、窄窗与减少动画。针对性单测、改动 lint、完整测试、隔离构建/编译和更新 macOS 测试包；生产副本冷启动/重启不干扰活动客户端。签名公证和跨系统仍单独标记未验收。

- Node 24.21.0：13 个启动/登录相关 TS 文件严格 lint、6 个定向测试文件共 63 项通过；完整测试 5,922 项通过、148 项跳过。后续首页样式调整后完整复跑同样通过。
- 浏览器使用真实登录组件和本地模拟 bridge 检查 60 秒成功提示、3 秒重发/5 秒过期、发送失败、2 秒发送中、换号清空 challenge 与切换平台忽略迟到响应。后台绝对期限计算有回归用例；切回窗口刷新监听按同一计算运行。
- 中英文/浅深色、480px 宽度正常；英文倒计时和脱敏提示没有横向溢出。真实 PlatformSessionGate 在 StrictMode 下完成配置/账户检查后进入登录页；浏览器 error/warn 日志为空。
- 独立 renderer build、Electron compile 和 macOS arm64 DMG 构建通过。生产副本冷启动和重启正常，深色首屏与保存的浅色偏好分别检查；主题缓存和系统/原生快照冲突在启动脚本 VM 测试中覆盖。原生启动过程未做逐帧录屏，不将最终截图作为每一帧均无闪烁的证明。

## 提交前窗口操作回归

自审补充 Windows 加载阶段的原有窗口操作栏，避免平台检查和引擎加载的全屏层覆盖关闭/最小化/最大化。保持已有窗口 IPC，不增加引擎调用。首次完整测试出现 8 项旧 EngineStartupOverlay 服务端渲染失败，原因是新展示组件读取不存在的 window；添加 window/bridge 可用性保护并补回归，不修改旧断言。最终完整复跑 5,926 通过、148 跳过；窗口及启动 3 文件 24 项通过，相关 lint 通过。浏览器模拟 win32 使用真实操作栏与 mock 窗口 API，三个按钮分别触发对应动作；Windows 真机仍未验收。
