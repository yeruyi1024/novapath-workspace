# 界面启动恢复与文件路径一致性

## 问题与范围

开发窗口首次加载完成后恢复控制器标记为 finished，后续手动刷新失败不再重试。React 模块导入失败不在组件错误边界的覆盖范围内，静态启动页缺少失败出口。文件成果检测和实际读取使用不同的路径拼接；POSIX 项目目录尾部合法的反斜杠可能被移除。

只修改窗口导航恢复、独立静态启动保护和路径解析；不清理用户数据、不修改凭据、不重启用户当前窗口。此前偶发热更新白屏尚未完整复现，不能把这些修复认定为所有白屏根因已消除。

## 验收条件与实现

- 已加载窗口的新导航重新启用有限重试；健康刷新不触发额外 reload。
- React 接管前发生脚本错误或等待超过 30 秒，静态页提供手动重新加载；不自动刷新。React 接管后取消计时和事件监听，不覆盖正在运行的界面。
- 文件成果与本地预览共用无 Node 依赖的 workspacePath 解析模块，统一 URL 单次解码、相对路径和 Windows 分隔符；POSIX 反斜杠保留。
- 不完整引用可保留用于检测展示，实际读取仍必须通过路径和文件校验；本轮没有新增越权文件读取入口。

## 验证

相关 6 个测试文件、138 项通过，覆盖刷新失败恢复、健康刷新、启动超时/错误/接管取消、Windows 与 POSIX 路径以及成果检测。旧 Windows 绝对路径测试更新为统一分隔符后的同一文件位置断言。启动保护使用独立 VM 执行脚本验证，不依赖 React 正常加载。

生产构建、Electron 编译、改动文件 ESLint 和 git diff --check 均通过。独立浏览器页面加载真实 startup.js 与样式，模拟模块启动错误，实际确认恢复提示及手动重新加载按钮；该页面不依赖或改动用户客户端。用户正在使用的客户端未重启；恢复按钮的 Electron 实际窗口验收、热更新白屏复现和 Windows/Linux 真机验收仍待完成。


## 启动与恢复链路重构

用户授权继续重构后，日志定位到外观 Provider/Scope 热更新错误及 Markdown 延迟组件预览错误。日志只保留错误类型与组件栈，不足以确定当时 TypeError 的全部细节；据源码与可重复测试修复对应结构缺口，不声称所有历史错误来自同一原因。

- 将外观 Context 与 hooks 从 Provider 组件模块拆出，统一消费者引用，保持热更新期间 Context 身份一致。
- 开发和生产窗口共用恢复控制器，移除旧生产 watchdog 重载和重复崩溃监听触发。失败事件/Promise 去重，旧导航 Promise 通过 generation 隔离；连续崩溃在稳定运行前保留预算，三次后进入手动恢复。
- 慢加载 30 秒记录诊断；90 秒仍未完成则进入错误页，不反复刷新。React 启动前的保护与组件错误边界继续保留。
- 错误页使用限制为主窗口主框架的 preload IPC 重试真实应用，而不是重载错误页。补齐安装包中 error.html 与 recovery.js 的声明。
- 非安装包的本地生产客户端将 dist 复制成进程生命周期内固定的临时快照，避免新构建清空旧窗口的延迟资源；退出时清理。正式安装包资源本身固定，无额外快照。
- 所有文件预览统一加局部错误边界；预览渲染失败不会把整个会话和侧栏一起卸载。切换文件使用独立边界，不展示文件内容或服务器错误原文。
