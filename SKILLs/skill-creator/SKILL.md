# 星途技能维护

本说明由星途重新编写。目录内保留的上游工具及其许可证仍归原作者；不要把它们标为星途原创。

## 明确目标

先从当前任务确认输入、输出、使用场景、必要工具和限制。已经明确的条件不重复询问；缺少会影响行为的信息时简短提问，并继续不依赖回答的工作。

技能提供工作说明，可以附脚本或参考资源；它不会凭空增加运行时工具。先检查当前可用工具、MCP 和本地依赖，使用实际可调用的接口。默认不下载软件、不上传文件、不更改用户账户。

## 编写技能

在用户指定或应用提供的技能目录中创建独立目录，使用小写英文和连字符作为标识。入口必须为 `SKILL.md`，YAML 头部至少包含 `name`、`description`，并在 `metadata.version` 中声明版本。描述要写清楚处理什么任务和何时使用。

正文保持简短，按执行顺序写出读取输入、处理、验证、交付的步骤。只附重复使用的脚本或确实需要的参考文件，使用相对路径并从正文引用。临时报告、用户凭据、真实业务样本不作为随包资源。

脚本路径通过 `SKILLS_ROOT` 定位；文档 Python 使用 `STARPATH_PYTHON`。考虑 Windows、macOS、Linux 的路径、编码和进程行为。不要硬编码开发机目录，也不要假定某个模型品牌或外部 CLI 已安装。

## 验证与交付

检查 YAML、资源路径和依赖，然后实际运行新增脚本。使用临时输入验证主要结果及有意义的失败情况；输入与输出分开，默认保留原文件。对文档检查内容和排版，不能只检查文件存在。

需要模型执行效果测试时，在当前应用的真实工具环境中执行代表性任务，记录结果和尚未验证的限制。没有测试能力时直接说明，不能虚构调用、指标或验收通过。目录中保留的外部模型专用评估脚本仅在对应工具确实可用且用户要求时使用，不作为默认依赖。

交付时说明用途、触发方式、新增资源、验证结果和版本。修改已有技能时保留用户配置与完整旧版本备份。内置技能随客户端发布；远程技能由其来源维护，不能承诺自动更新。

## 来源要求

独立编写的新材料记录作者与许可证；使用外部脚本、字体、模板或图片前核对再分发许可，保留要求的声明。没有明确许可的材料不要进入发行包，不能通过换名字、删除署名或重写许可证解决授权问题。
